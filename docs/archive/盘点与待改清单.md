## 四、`incoming` 采集细节问题

### 4.1 `agent_p1.jsonl`（arena_elo）
- **日期粒度不一致**：`text` 快照 `2026-08-21`、`coding` `2026-08-01`、`math` `2026-08`（月级）。同一模型不同子榜抓到不同快照日，合并主键 `(sub_benchmark, date)` 下会并存多日期，建议统一快照日精度。
- `is_primary` 字段 540/540 均已填，与 schema 一致 ✅（非问题）。

### 4.2 `agent_p2.jsonl`（independent）
- **`source_url` 为 null 占 96/155（62%）**：全部是 T3「第三方登记站」条目。校验器对 `independent` 要求 `source_url` 必填 → 合并后整体校验会报大量 ERROR。
- **`source_type` 词汇爆炸**：18 种子类「第三方登记站（xxx）」（llmbase / benched.ai / evals.report(Verified)/(Unverified) / tpsreport.news / serenitiesai …），缺乏受控词表，后续分析难聚合。
- **数组主键重复 3 组（真实 bug）**：`evals.report` 的 `(Verified)` / `(Unverified)` 两条被统一成 `config='default（evals.report）'` 同键（`GPQA Diamond`/`MMLU-Pro`/`SWE-bench Verified`，date `2025-06`）。合并工具 `union_by_key` **对同文件内重复主键不去重** → 合并后会产出重复条目。
- `score` 0–1 合规 ✅；`confidence` T1=59 / T3=96 分布合理。
