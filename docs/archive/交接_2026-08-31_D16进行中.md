## 1. 这个项目在做什么

`model_data_v2.jsonl` 是一份**多厂商大模型元数据主库**：每条记录一个模型，覆盖基本信息、架构、跑分（自报 / 独立 / Arena ELO）、定价、模态、采集溯源。用途是给下游做「模型能力 × 成本」横评，因此数据的**可机器聚合性**（枚举、单位、主键）和**溯源诚实性**（不许伪造默认值、不许把三方转述当官方）是核心质量目标。

工作方式：多个 agent 分批次（305 批）从公开来源采集，产出 `incoming/models/*.jsonl` 采集文件，再由合并脚本写进主库；`docs/batch_claim_ledger.jsonl` 是批次认领台账，也是**模型名册的唯一可靠来源**。我这一路（workbuddy-03/04/05 → 本会话）负责的是**采集完成之后的质检与整改**：发现口径不一致、schema 漂移、语义混杂的地方，量化后提请用户拍板，再一次性批量整改，并用门禁规则把结果焊住防回归。

## 6. D16（唯一未完成的任务）：`pricing.free_tier` 形状统一

### 6.1 问题是什么

同一个字段在库里目前有**四种形状**（本文实测，`collections.Counter(type(...).__name__)`）：

| 形状 | 条数 | 说明 |
|---|---|---|
| `null` | 718 | 未采集 / 无免费额度，合规 |
| `dict` | 134 | **已是规范对象**，键序全部一致为 `[available, rpm, rpd, tpm, notes]`；134 条 notes 全部非空；仅 **3 条** rpm/rpd/tpm 有数字；`available` 分布 `None 56 / True 52 / False 26` |
| `str` | 52 | 一句自由文本，例：「新用户开通百炼后 90 天内各模型有免费额度（以控制台为准）」 |
| `bool` | 29 | 裸 `true` / `false`，信息量最低 |

**根因是文档与门禁互相矛盾**（这是本轮最有价值的教训）：
- `docs/prompt.md:527` 教的是字符串写法：`- free_tier：免费额度描述，如 "每月 100 万 token 免费"，无则 null。`
- 门禁的 `SUB_BLOCK_KEYS` 白名单是对象。
- 采集 agent 照文档写 → 写成字符串 → 门禁不报（只在 dict 时校验）→ 漂移累积。
- 另有三处模板同罪（只写了 `"free_tier": null` 而未给对象示例）：`docs/prompt.md:493`、`docs/agent_prompt_per_model.md:51`、`docs/执行细则.md:127`。`docs/prompt.md:714` 的示例记录里 `free_tier` 恰为 `null`，不冲突但也无示范作用。

### 6.3 我对第 19 轮的落地解释（**写下来供确认，尚未获用户明确认可**）

1. `available` 的语义是「**存在某条免费途径**」（App / Web / 聊天页 / Playground / 试用 key / 新用户额度 …任一），**不是**「这个模型免费」。
2. 因此 `available=true` **绝不参与、也不得抵消**价格判断：真实是否免费**只看官方 API 定价键**（`pricing.input` / `output` / `cached_input` / `batch_*` 及它们的 `confidence`）。合并/统计脚本**不得**用 `free_tier.available` 推价格。
3. `available=true` 时 `notes` **必须写清是哪条免费渠道**（否则该键失去可核性）。
4. 反面：「随订阅提供」「付费计划内含额度」= **有渠道但渠道本身要付费**，第 19 轮的「任一途径」是否包含付费订阅，**必须问用户**（见 §6.5 的 4 条 cursor）。

## 7. 坑（都实测过，别重复踩）

**环境/工具**
1. **Windows 编码**：任何 python 输出前先 `PYTHONIOENCODING=utf-8 PYTHONUTF8=1`，否则中文乱码。
2. **门禁用法**：`python scripts/validate_model_data.py <file>`（**位置参数**，裸跑报错）；`--report` 需真实文件路径。
3. **`--report /dev/stdout` + `grep -c` 会假阴性**（曾据此差点写出错误结论）：管道吞输出导致「命中 0」。→ 写真实报告文件再统计，并用独立 python 复核。
4. **陈旧 `origin/main` 引用会虚报未推送数**：报推送状态前先 `git fetch`，并看 `git ls-remote origin refs/heads/main`（远端权威值）。
5. **curl 的 000 / `CRYPT_E_NO_REVOCATION_CHECK` 不代表死链**（本机 schannel 吊销检查被阻断）。验证 URL 用 `git ls-remote -q <repo>` 或 WebFetch。
6. **push 连不上是边缘 IP 闪断**，不要治网络（别改 hosts、别关 `http.schannelCheckRevoke`），**后台循环重试 `git push` 即可**（上次第 9 次、约 5 分钟后成功）。
7. **`HTTP_PROXY` 指向死代理会伪装成「网络不通」**：`unset HTTP_PROXY HTTPS_PROXY` 后直连。
8. **认领批次后要先 `git add` ledger 再 commit**，否则「no changes added」静默失败。
9. **合并是填骨架不是加记录**：主库 702 条骨架早由 HF API 快照预填，合并必须 `--on-both source_wins`；用 `conflict` 会一个字段都不写。
10. 门禁三个高频踩点：`release_date` 只写年份 → ERROR；参数量为空时 `notes` 必须含**字面**「未披露」或「待补」；CRLF→LF 警告是噪音不是错误。
11. 名册比对**只认 `docs/batch_claim_ledger.jsonl`**；用 `intermediate/roster.jsonl` 会得到 80 的错误答案（正确是 26）。

**方法/判据**
12. **脚本的匹配条件就是它的盲区**：读路径能静默产出「0 命中」。每一条被接受的命中都必须打印证据与原句上下文；保守偏差方向（少填/判不动）要显式说出来。
13. **口径要先量化再定**，别按设想拍板：D11 曾设想「两源分数打架」，实测 38/39 组 `confidence` 全同，真实毛病是主键不足；D13 废止的口径也是先测出 173/208 与设想背离。
14. **数字要按「脚本实际操作的那份数据」来报**。曾把 940 条快照上测的「195 种」写进 5 份文档，而 D15 实际操作的 933 条库上是 **190 种（186 种越界 / 289 处）**——必须交叉核对 `git show HEAD~1:...`。
15. **不要写未经核实的库内「原话」**，也不要凭印象点名记录（曾出现库里根本没有的 `RS-vHeat`）；一切引文用脚本从备份里抽。
16. 判「含免费字样」时要小心**排他式否定**：#20 grok-4-heavy 的「X 平台免费版仅限 Grok 3/4」是在说**它自己没有**。
17. **兄弟型号的声明不得算到本条头上**；一条记录里的限定语窗口要**按子句切**，按 ±30 字符切会吞掉上一子句（D15 的 stepfun 案例）。
