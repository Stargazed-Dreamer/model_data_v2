# model_data 可视化技术栈方案（供决策）

> 撰写于 2026-08-25。基于对 `model_data_v2.jsonl` 的实际盘点。

---

## 1. 数据现状（决定方案的三个事实）

1. **规模小**：当前 927 条记录（目标约 1000+），JSONL 单文件，全量加载 < 5 MB。**不需要数据库也能跑得飞快**。
2. **嵌套深、稀疏不均**：8 个顶层键（`basic_info/architecture/benchmarks/pricing/modality/meta`...），定价填充率低、跑分条目不定长（`self_reported/independent/arena_elo` 是数组）。可视化前必须做一层"展平+聚合"转换。
3. **持续增量**：M 型/P 型 agent 还在慢慢补数据，方案必须支持"一键刷新"，不能每次手工导出。

---

## 2. 技术栈候选对比

| 方案 | 组成 | 开发量 | 刷新体验 | 交互能力 | 风险 |
|------|------|--------|----------|----------|------|
| **A. 单文件静态页** | Python 脚本展平 JSONL → 一个自包含 `dashboard.html`（内联 ECharts + 数据） | 半天 | 重跑脚本重新生成 | 图表筛选够用，复杂联动弱 | 几乎无风险 |
| **B. 本地 Web 应用**（推荐） | **FastAPI + ECharts + Vue3(CDN)**，FastAPI 直接读 JSONL 实时转换，无构建步骤 | 1-2 天 | 打开页面即最新数据 | 自由度最高：筛选器、对比表、下钻随便做 | 无新依赖，复用项目已有 FastAPI 经验 |
| **C. Streamlit** | Python 全栈，几十行出仪表盘 | 2-4 小时 | 文件变化自动重载 | 组件化布局，定制图表样式受限 | 引入新框架；样式丑且难调 |
| **D. BI 工具（Metabase/Superset）** | 需先把数据入库 + Docker | 高 | 自动 | SQL 视角，嵌套数组类字段很难看 | 明显过重，杀鸡用牛刀 |
| **E. PySide6 桌面 GUI** | 复用本项目 UI 设计系统 + QtCharts/pyqtgraph | 3-5 天 | 手动刷新按钮 | 强，但图表生态弱于 ECharts | 开发成本最高；浏览器方案已足够时不值得 |

### 结论与推荐

**推荐方案 B**：FastAPI 后端（读 JSONL → 展平/聚合为视图 JSON）+ ECharts 前端单页（Vue3 用 CDN 引入，不走 npm 构建）。理由：

- 数据只有千条级，**实时读文件转换即可，毫秒级响应**，SQLite/DuckDB 都可以省掉；
- 与项目现有技术栈（FastAPI）一致，零新增重型依赖；
- ECharts 是中文文档最好、交互最丰富的图表库，适合后续扩展；
- 不需要 node/npm 构建链，维护成本最低。

**备选**：如果只想快速看一眼、不想起服务，先花半天做 **方案 A** 作为过渡（同一份展平脚本可复用到 B）。

## 3. 方案 B 架构

```
model_data_v2.jsonl ──► FastAPI (port 8620)
                          ├─ GET /api/models      # 展平后的模型宽表（供表格/散点）
                          ├─ GET /api/aggregates  # 预聚合统计（厂商分布/填充率/ELO Top）
                          └─ GET /                # 静态 index.html（ECharts 页面）
```

- 后端只做两件事：**展平**（嵌套 → 一行一模型的宽表）和 **预聚合**（图表直接可用），前端不做任何数据加工逻辑。
- 数据更新后刷新页面即生效（每次请求现读现转，927 条开销可忽略）。

## 4. 页面规划（初版 4 个模块）

1. **总览 KPI 卡**：模型总数 / 厂商数 / 各关键字段填充率（定价、上下文窗口、多模态、跑分）——顺带监控抓取进度；
2. **厂商维度**：厂商 × 模型数量条形图、发布时间轴（release_date 分布）、开源 vs API 分布；
3. **性能视角**：Arena Elo 排行榜（Top-N 表格）、价格(input/output) vs Elo 散点图（找性价比）、独立跑分对比条形图；
4. **明细浏览表**：全量宽表 + 多维筛选（厂商/开源/上下文长度区间/模态），点击行展开原始嵌套详情。
