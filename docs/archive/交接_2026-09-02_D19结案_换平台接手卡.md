## 1. 这个项目在做什么

`model_data_v2.jsonl` 记录各家厂商的大模型元数据：架构、参数量、上下文窗口、定价、发布时间，
以及三组跑分条目（`benchmarks.self_reported` 厂商自报 / `benchmarks.independent` 独立评测 / `benchmarks.arena_elo` 竞技场分）。

数据由多个采集 agent 分批产出，本仓库这一侧的职责是**质检、归一、去重、裁决口径**，产出：
- 一个门禁脚本（`scripts/validate_model_data.py`），把口径固化成可执行规则；
- 一份机制指南（`docs/WORKBUDDY_AGENT_GUIDE.md`，§1–§27.6）；
- 一份质检结论台账（`docs/qa_report.md`，文首补记 21 项）；
- 一份采集 SOP（`docs/prompt.md`，给下游采集 agent 看的）。

**「整改轮 D1…D20」是什么**：2026-08-29 起，每一轮做一件事（清一类缺陷或补一条门禁规则），
每轮都：先独立实测数量 → 需要人定方向的**逐条提请用户拍板** → 改 → 跑 rails 验收 → 同步四类文档 + 记忆 → 提交推送。
轮次字母后缀 `b/c/d/e` 表示同一主题拆成的连续小轮（如 D18 → D18b → … → D18e）。

**用户的两条总口径（仍然有效，是本轮所有决策的根据）**：
1. **「除了重采全做，需要拍板的一条一条问我」** —— 凡是要回原始来源重新采集的，一律不动、登记待办；能靠库内证据判断的，做完但先要裁决。
2. **「能 push 的话及时 push」** —— push 已预先授权，不必每次问。

还有一条已升级为记忆的：**「按你的顺序做你能做的」** —— 自主排序、连续推进、只做不需他在场的项；需要裁决的落成文件等批，别停等也别逐条打断。

## 2. 怎么跑（命令原文照抄可用）

```bash
# 跑门禁（唯一权威判据）。--report 必须给普通文件路径。
PYTHONIOENCODING=utf-8 python scripts/validate_model_data.py model_data_v2.jsonl --report temp/check.md

# 只读 HEAD 那一版的数据（取改前快照做负对照）
git show HEAD:model_data_v2.jsonl > temp/head_data.jsonl
# 取改前的门禁脚本
git show HEAD~1:scripts/validate_model_data.py > temp/gate_old.py
```

**序列化约定**（改数据前必须先验，别猜）：本库是
`json.dumps(obj, ensure_ascii=False)` + **默认分隔符**（不是 `separators=(',',':')` 的压缩写法），
纯 LF，文件以换行结尾。实测 933/933 行往返逐字节相同（`temp/d19_roundtrip_check.py`）。
**改键序 = 改字节** → 逆还原类验收会整体作废，所以新增键必须按约定位置插（见 §4）。

**环境陷阱（Windows / Git Bash，都是实测踩过的）**：
- Git Bash 控制台是 GBK —— 脚本里的中文**不要 `print` 到 stdout 就好**，要写文件必须 `io.open(path, "w", encoding="utf-8")`；跑子进程必须带 `PYTHONIOENCODING=utf-8`。
- `python -c "...反引号..."` 会被 bash 吃掉 → 用 `<<'EOF'` heredoc 或写成 `temp/*.py`。
- `/tmp` 不可用，临时文件一律放 `temp/`（已 gitignore）。
- 是 `md5sum` 不是 `md5`。
- `%TEMP%\pytest-of-admin` 的 ACL 已被毒化，任何项目跑 pytest 默认启动即 `PermissionError` → 需要 `--basetemp`。
- `--report /dev/stdout` 这类管道会吞输出，造成「命中 0」假阴性。
- github.com 直连有边缘 IP 闪断，push 失败**只能重试**，不要改用其他方式。
- `git status` 的「ahead N」**未 fetch 时不可信** → 报「已推送」前必须 `git fetch` 再 `git rev-list --left-right --count origin/main...HEAD`。
- 采集花名册只认 `batch_claim_ledger`，别的文件都是旧快照。

## 8. 十轮整改推翻的直觉（冷启动必读，比任何具体数字都值钱）

完整正文在记忆 `docs/memory/project/project-stage3-gaps.md` 的「十轮整改推翻的直觉」节和指南 §26 / §27 各小节。这里只留最锋利的十一条：

1. **D11**：「同名基准分数冲突」这个题目本身问错了 —— 不是来源打架，是**主键不足以标识一次测量**。处置是补主键，不是裁决取哪条。
2. **D13**：一条**没人记得来历的口径**能撑住全库 1/3 的警告。规矩背离数据到这个程度时，用户选的是**废止规矩**，不是补数据去迁就规矩。
3. **D14**：「我们只记录模型」听起来天经地义，但它是一条**从没写下来、也从没被检验过**的范围假设。破坏性指令（「把 Unknown 的全删掉」字面命中 376 条）**必须先量化出几种读法各自的数量再确认**。
4. **D15**：一栏里混两种语义时，正解是**拆成两个受控枚举栏 + 原文进 notes 留证**，不是再叠关键词规则。限定语/否决窗口**按字符数切一定会跨过子句边界误伤**，必须按子句切。
5. **D18**：**提请拍板前，数量必须按「缺陷类」全库数一遍，不能只数「本轮筛出来的那批」** —— 筛选条件会悄悄给数量定了范围。**登记任何遗留清单时必须同时写下判据原文、该判据的命中数、以及放宽判据后的命中数。**
6. **D18b**：**说「某缺陷已清零」之前，先问判据查的是字段语义还是字符串表面属性。** 子串匹配能被一个语义完全不同的值满足。验收全绿不等于判据在查你以为它在查的东西。
7. **D18c**：**把信息从 A 栏搬到 B 栏之前，先确认 B 栏的合法值表能接住 A 栏的写法**；接不住的那几条单独拎出来登记，**不要为了让变换统一而改写它们**。一个变换的「统一性」不能凌驾于目标栏的合法值表之上。
8. **D18d**：**「WARN 没动」不等于「这轮什么都没做」，但要拿得出证据。** 价值是纯语义的改动，别包装成质量指标提升。归一/剥离类改动必须**同时报「含目标属性的条目数」与「写法种类数」两个量**，否则「归一重复写法」与「给条目加上/摘掉属性」在验收上无法区分。
9. **D18e**：**新规则在现库命中 0 时，必须自己造正对照探针** —— 「没接通」与「库真干净」在门禁输出上完全无法区分。
10. **D19**（本轮新增）：**报「WARN 没动」要分两个方向看，两者都不成立。** D18d 改了数据而门禁照不到（数据 md5 动）、D18e 改了门禁而库本来就干净（门禁 md5 动），两轮都表现为基线不变 —— **唯一判据是哪个 md5 动了**。
11. **D20**：**判据只认「以 X 开头」，就一定有镜像形活着。** 把 D20 新加的「任意位置」判据在**全部 26 个备份**上跑，从最早的 5467 条目那份到现盘，**命中数一字不变全是 21** ——
    说明这一类写法**从建库就在，17 轮整改一次都没碰过它**，唯一的原因是没有任何一条规则指向过那个形状（前缀类有 6.4、整栏类有 6.3，后缀类两头都不沾）。
    **可复用的动作**：每写下一条「位置敏感」的判据（以 X 开头 / 结尾 / 整栏等于 X），当场把它的**镜像形与中间形各扫一遍**并记下命中数；命中不为 0 就必须要么补规则要么显式登记「刻意不管」。

**通用验收 rails（整文件类改动的标准配方）**
反向还原必须与改前逐字节相等 + 同时锁记录数与条目数 + `score` 多重集相同 + 字段级 diff 只允许预期键且越界路径 0 +
未参与条目零改动 + 新检查项要在改前备份上跑负对照 + WARN 逐级记账且每级差额都对上一个可独立测量的量 +
序列化往返先验（约定猜不得）+ **打印语句与断言不一致时以断言为准、但那行打印必须当场修掉**。
