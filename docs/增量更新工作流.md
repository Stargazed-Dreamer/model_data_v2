> 建立于 2026-09-06。主库首批采集截止 2026-08-29（collected_at 口径），本流程定义**之后的新发布如何持续入库**。
> 所有质量口径不变：门禁 `scripts/validate_model_data.py` 是唯一权威判据；红线（不伪造 T0、缺错降级、confidence 枚举）全部沿用。

| 环节 | 频率 | 重量 |

## 1. S0 发现

**信息源：见 `跟踪源清单.md`（2026-09-10 建立，S0 的唯一清单入口）**。分层用法：

- **A 层聚合 API（首选，结构化可 diff）**：`openrouter.ai/api/v1/models`（实测 435 模型，带 `created` 上架日）、`huggingface.co/api/models?author=<org>`（带 `createdAt`）
- **B 层官方一手（定档必须回这里）**：各厂商 news / 开放平台台账页；已验证的范本是阿里云百炼《模型上下架与更新》（逐条带日期 + model_id）
- **C 层榜单交叉**：epoch.ai 本地 CSV、LMArena、Artificial Analysis、OpenCompass
- **D 层中文盘点**：知乎月度盘点、量子位/机器之心、新华网/光明网（只能出 `T0-自报-转述` / `T3`）

⚠ 两条铁律（详见 `跟踪源清单.md` §4、§5）：
1. **OpenRouter 的 `created` 是上架日，不是发布日**（实测 LongCat-2.0 发布 06-30 / 上架 07-20，滞后 20 天）；
2. 本机 curl 必须加 `--ssl-no-revoke`，否则 HTTPS 一律失败。

**产出**：`temp/d<轮>wave<序>_candidates.jsonl`，每行一条：
```json
{"name":"GPT-6 Astra","vendor":"openai","release_date":"2026-09-03","tier":"T1","evidence":"https://...","note":"一句话要点"}
```
**红线**：查不到日期/来源的记 T3 并在 note 标「待二查」，不硬填。

## 2. S1 范围判定

```bash
PYTHONUTF8=1 python scripts/candidate_diff.py temp/<候选文件>.jsonl
```
输出三档**建议**（仅供人工复核，不自动处置）：`NEW`（库内未见）/ `CHECK_VARIANT`（家族已有、版本相邻）/ `EXISTS`（疑似已有）。

逐条三问：
1. **是不是模型**？训练系统 / agent 框架 / 文档解析工具 → 非模型，参照 §23 惯例登记（`docs/non_model_records.jsonl` 同类），不采集。
2. **是不是新的**？已有模型的 API 快照 / 思考档 / 尺寸档 = **变体**。判定并入现有记录还是新开一行，依据 D35 教训：**一行一个独立的"测量身份"**（如思考/非思考两档必须分行并保证 full_name 可区分）。
3. **在不在范围**？release_date ≥ 2022（D31 口径）。

**拍板点①**：候选名单（采集哪些、缓哪些、舍哪些）需用户确认。

## 3. S2 采集

1. `docs/batch_claim_ledger.jsonl` 追加新批次（batch_id 命名延续 `bNNw<序>` 惯例，可在 note 标注 `增量-<年月>`）；
2. 每模型派一个 subagent：任务书用 `agent_prompt_per_model.md` 模板，字段口径 = `prompt.md` + `执行细则.md`，多平台时的并发/认领协议 = `multi_platform_subagent_guide.md`；
3. 产出落 `incoming/models/<batch_id>__<vendor>__<model>__<variant>.jsonl`（超长路径按指南 §8.1 降级）。

## 4. S3 门禁与合并

```bash
# 单文件门禁：ERROR 必须 0
PYTHONUTF8=1 python scripts/validate_model_data.py <file>

# 合并（新模型走 add_record 自动补完整骨架；同 id 已有记录走 fill_null/source_wins）
PYTHONUTF8=1 python scripts/model_data_tool.py merge --file model_data_v2.jsonl --incoming <f> \
  --on-null take_source --on-both source_wins --on-array replace --on-schema upgrade --tie-breaker keep_target --apply
```
⚠ 三条硬约束（历史事故背书）：
- 空数组保护默认开启（§18 事故）；跑分数组并集主键 `benchmark,config,date`（independent 加 `source_site`；arena_elo 用 `sub_benchmark,date`）；
- 合并后跑收尾三自检：数组缩水取证、撞键分类、WARN 基线差值（现基线 **ERROR 0 / WARN 0**，任何上涨都要解释）；
- `collected_at` 不得伪造早于实际采集日。

## 5. S4 增量质检

- 门禁全库复跑（基线见上）；
- `temp/d34_scan_outliers.py` 复扫（31 项门禁外体检：离群/矛盾/重复/覆盖率），新入库记录是重点观察对象；
- `scripts/candidate_diff.py` 复跑上轮候选：已入库的不再报 NEW；
- D36 起**价格量级锚点**已入 notes 惯例：新定价记录若与同厂后继/前代差 10× 以上，必须复核单位口径。

## 6. S5 发布

CHANGELOG 追加 `<D轮>` 条目 → commit → push。viz 服务现读 JSONL，刷新页面即见新数据。

## 7. 每轮固定拍板点

1. 候选名单（S1 产出）；
2. 变体归属：并入现有记录 vs 新开一行；
3. 非模型判定；
4. 批次大小与是否多平台并发。
