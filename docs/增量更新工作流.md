## 1. S0 发现

**信息源：见 `跟踪源清单.md`（2026-09-10 建立，S0 的唯一清单入口）**。分层用法：

- **A 层聚合 API（首选，结构化可 diff）**：`openrouter.ai/api/v1/models`（实测 435 模型，带 `created` 上架日）、`huggingface.co/api/models?author=<org>`（带 `createdAt`）
- **B 层官方一手（定档必须回这里）**：各厂商 news / 开放平台台账页；已验证的范本是阿里云百炼《模型上下架与更新》（逐条带日期 + model_id）
- **C 层榜单交叉**：epoch.ai 本地 CSV、LMArena、Artificial Analysis、OpenCompass
- **D 层中文盘点**：知乎月度盘点、量子位/机器之心、新华网/光明网（只能出 `T0-自报-转述` / `T3`）

⚠ 两条铁律（详见 `跟踪源清单.md` §4、§5）：
1. **OpenRouter 的 `created` 是上架日，不是发布日**（实测 LongCat-2.0 发布 06-30 / 上架 07-20，滞后 20 天）；
2. 本机 curl 必须加 `--ssl-no-revoke`，否则 HTTPS 一律失败。

### 1.1 S0-a 差集式（新面孔）

抓 A 层聚合 API 与榜单最新快照，只取「相对上轮基线新增」的条目。快、够用，**但结构上捞不到「基线期就已在榜/在架、而库内一直没有」的条目**。

### 1.2 S0-b 榜单全量反推（**必做，不是可选**）

> 立规于 2026-10-01（D52）。起因：`glm-5.3-max` 在 Arena 2026-09-11 快照就已单列独立 elo，
> 而 D51 用的是纯差集式 S0 ⇒ 它不属「新面孔」，被整轮漏掉，一路挂到 D52 才靠人工发现。
> D39 早就用过全量反推（一次挖出 84 条疑似漏采），但当时只当一次性动作、**没有写成常规步骤**，
> 于是后面几轮又退回差集式，缺陷重复出现。本小节把它固化为每轮 S0 的固定动作。

做法（脚本已固化为常驻工具，可直接跑）：

```bash
# ① 抓最新榜单快照（覆盖 temp/d39_arena_raw.json）
PYTHONUTF8=1 python scripts/d39_fetch_arena_leaderboard.py
# ② 榜单逐条回查主库 → 未被命中的按基础名聚合 → 分「疑似命名差异」与「疑似真漏采」
PYTHONUTF8=1 python scripts/arena_gap_reverse.py --out-dir temp/d<轮>
```

> `scripts/arena_gap_reverse.py` 是 **D52 新增的常驻工具**（此前只有 `temp/d39_gap_from_arena.py`
> 这个一次性脚本，`temp/` 不入库、被清理后方法就丢了 —— 这正是它后来退化成差集式的直接原因）。
> 改它的命中/过滤口径前，请先跑一次并与 `temp/d<轮>/arena_gap_raw.json` 的历史两档数对比。

命中判定 = **先 `modelCode`、再 `modelName`（去变体标记后归一）**，任一命中即算「库内已有」。
`difflib` 相似度 ≥ 0.72 判为「疑似命名差异」（**不可尽信**，D39 曾把 `Claude Opus 5` 错配到
`claude-opus-4-5-…`；反过来本轮的 `Opus 4.5` ↔ 库内 `claude-opus-4.5-…` 因归一后是超集关系、
相似度仅 0.667 而被误判成漏采 ⇒ **两档都必须人工复核，不能只看档位**）。

反推产物是 **S0 候选，不是采集清单**，一律要过 S1 三问（是不是模型 / 是不是新的 / 在不在范围）。
本轮实测还需额外剔除三类：① 匿名 / 实验代号（`amazon-nova-experimental-chat-*`）；
② 老社区模型（vicuna / alpaca / oasst / GPT4All / mpt / stablelm 等，**未必符合本库「主流大模型」口径**）；
③ 归一后与库内某条互为超集关系的命名差异。

**产出**：`temp/d<轮>/arena_gap_raw.json`（两档明细）+ `temp/d<轮>/arena_gap_candidates.jsonl`（S0 格式）。

### 1.3 反推候选的四分类复核（S1 前置筛，D52 固化）

`S0-b` 产出的「未命中」清单**不是采集清单**，先做一遍四分类再进 S1：

| 类 | 判据 | 处置 |
|---|---|---|
| **A 已在库** | 归一化后与库内 `model_id` / `full_name` **互为包含**，差异属**档位 / 日期 / 服务后缀** | 不动（必要时在 notes 补别名） |
| **B 非范围** | 社区微调（zephyr / vicuna / alpaca / openchat / starling / dolphin / guanaco / openhermes / nous-hermes / stripedhyena / oasst / fastchat / stablelm-tuned / smollm / gemma-…-simpo 等）；LMArena **匿名实验快照**（如 `amazon-nova-experimental-chat-*`，无正式发布名） | 剔除，不进采集清单 |
| **C 同族已有·该变体未采** | 该厂商在库内**已有同族记录**，但**此具体变体**（更小 / 更老 / 特定规格）未采 | 列入 S1，按「是否主线」判定 |
| **D 真候选** | 库内该厂商**完全没有**此模型（含库内尚无节点的厂商） | 进 S1 三问 |

⚠ **判据三坑（D52 实测，必须防）**：

1. **别用裸子串匹配** —— 核心 token 过短会**跨厂商误匹配**（`GPT-5-Pro` 命中 `yandex:yandexgpt-5-pro`；`Nova 2 Lite` 命中 `amazon:nova-2-pro`）⇒ 候选带厂商时**只在同厂商池内比**。
2. **别把厂商主线当社区微调** —— 判前先查「**该厂商是否已在库**」（Reka / AI21 Jamba / 01.AI Yi / TII Falcon / Databricks DBRX / Upstage Solar / Cohere 库内都有节点）；排除表只管**明确的第三方社区微调**，边界项（如 NexusFlow Athene）单列待判。
3. **修饰词必须先归一** —— 榜单 run name 与库内主键的差异集中在 `chat` / `preview` / `high` / `thinking` / `instant` / `turbo` / 6–8 位日期后缀 上（`GPT-5.2 Chat` = `openai:gpt-5.2:base`、`Opus 4.5` = `anthropic:claude-opus-4.5-…-16k:base`、`Kimi K2.5 Instant` = `moonshot:kimi-k2.5:base`）；不归一就会把「已在库」整批误报成「真漏采」。

参考实现（D52 起可作下次起点）：`temp/d52/d52_gap_candidates_final.py`（四分类映射 + 70 条逐条判读 + 覆盖自证），前置脚本 `_triage.py` / `_v2.py` / `_v3.py` 记录了三轮判据修正过程。

**产出**：`temp/d<轮>wave<序>_candidates.jsonl`，每行一条：
```json

```

## 2. S1 范围判定

```bash
PYTHONUTF8=1 python scripts/candidate_diff.py temp/<候选文件>.jsonl
```
输出三档**建议**（仅供人工复核，不自动处置）：`NEW`（库内未见）/ `CHECK_VARIANT`（家族已有、版本相邻）/ `EXISTS`（疑似已有）。

逐条三问：
1. **是不是模型**？训练系统 / agent 框架 / 文档解析工具 → 非模型，参照 §23 惯例登记（`docs/non_model_records.jsonl` 同类），不采集。
2. **是不是新的**？已有模型的 API 快照 / 思考档 / 尺寸档 = **变体**。判定并入现有记录还是新开一行，依据 D35 教训：**一行一个独立的"测量身份"**（如思考/非思考两档必须分行并保证 full_name 可区分）。
3. **在不在范围**？release_date ≥ 2022（D31 口径）。

**拍板点①**：候选名单（采集哪些、缓哪些、舍哪些）需用户确认。

## 4. S3 门禁与合并

```bash
# 单文件门禁：ERROR 必须 0
PYTHONUTF8=1 python scripts/validate_model_data.py <file>

# 合并（新模型走 add_record 自动补完整骨架；同 id 已有记录走 fill_null/source_wins）
PYTHONUTF8=1 python scripts/model_data_tool.py merge --file model_data_v2.jsonl --incoming <f> \
  --on-null take_source --on-both source_wins --on-array replace --on-schema upgrade --tie-breaker keep_target --apply
```
⚠ 三条硬约束（历史事故背书）：
- 空数组保护默认开启（§18 事故）；跑分数组并集主键 `benchmark,config,date`（independent 加 `source_site`；arena_elo 用 `sub_benchmark,date`）；
- 合并后跑收尾三自检：数组缩水取证、撞键分类、WARN 基线差值（现基线 **ERROR 0 / WARN 0**，任何上涨都要解释）；
- `collected_at` 不得伪造早于实际采集日。
